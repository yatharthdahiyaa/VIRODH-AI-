Platform

One gateway. Four ways to use it.

Put Virodh in the request path like nginx, call it as a scanning service, or run it in shadow mode first.

A reverse proxy that understands images

Clients keep their OpenAI SDK. Virodh authenticates the key, inspects the request, forwards only what the policy allows, and re-checks the answer.

  • /v1/chat/completions, streaming included
  • Blocked requests get a clean refusal or an API error, per policy
  • Fail-closed: if inspection fails, nothing is forwarded

How it works

Five checks between the user and the model

Each one is explainable on its own. Together they decide in a few seconds on a laptop CPU.

01

Ingress

Validate, re-encode and resize the image exactly as the model will see it.

+

Size, pixel and format limits stop malformed files and decompression bombs. Metadata is stripped. The model-resolution view is what gets inspected, so text that only appears after downscaling is not missed.

PNG2000×1000 → 640×320 model view · EXIF removed
02

Extract

Read every piece of text an attacker could hide in an image.

+

OCR on several views (mirrored, rotated, contrast-boosted), QR decoding, and decoders for base64, reversed text and word-substitution puzzles.

un-mirror“Steps to synthesise …”
base64“Explain how to bypass …”
03

Detect

Injection, harm, cross-modal combination, obfuscation and adversarial noise.

+

A policy classifier judges each text on its own words, Prompt Guard scores injection, and a composite check catches requests that are harmless in each half but harmful together (FigStep-style).

injection0.94
composite (prompt + image)0.71
04

Decide

Calibrated fusion → ALLOW, REVIEW or BLOCK, then your policy.

+

Thresholds are set on a validation split, never on the test set. Operator rules and blocked phrases apply on top. If any required check fails, the request is held — it is never allowed through uninspected.

REVIEWfail-safe: classifier unavailable
05

Verify

Wrap images as untrusted, then check the reply before releasing it.

+

Forwarded requests carry a security notice that image text is data, not instructions. If the reply still obeys a hidden instruction, Virodh withholds it.

WITHHELDreply output “ZEBRA-7” from hidden text

Security

Engineered like infrastructure

The gateway is designed to fail safely under load, outages and hostile input.

Under load

  • Bounded inspection slots per worker
  • Load shedding with 503 + Retry-After
  • Shared rate limits across workers
  • Identical inspections cached

When things break

  • Fail-closed on inspection errors
  • Circuit breaker per model provider
  • Timeouts on every external call
  • Health and readiness probes

Against hostile input

  • Body, image and pixel limits
  • Uninspectable content is rejected
  • Remote images off by default; SSRF-guarded when on
  • The model receives the exact bytes inspected

Deployment

From a laptop to a cluster

One server

Several worker processes on one port; SQLite keeps limits and logs shared.

python scripts/virodh_serve.py --workers 3

Cluster

nginx load balancer in front of N stateless gateway replicas.

docker compose -f deploy/docker-compose.yml up --scale virodh=3

Behind your nginx

Route /v1/ through Virodh; keep the rest of your stack.

location /v1/ { proxy_pass http://virodh; }
Honest limits

What Virodh does not do yet

Security products should say where they stop.

  • Detection is evaluated on ≈50 cases per attack; a held-out instruction phrased like a friendly note still slips past the classifier (the reply check catches it).
  • The adversarial-noise detector trades sensitivity for fewer false alarms on noisy photos; on its own it can only hold a request, never block it.
  • Classification uses hosted models (configurable); fully on-premise classifiers are future work.
  • Audio, files and tool outputs are not inspected; the gateway rejects content it cannot inspect.
